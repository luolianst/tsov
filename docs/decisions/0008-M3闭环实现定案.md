# ADR-0008 · M3 闭环实现定案：语义层/LLM 分析/MIDI 导出/fluidsynth 回放

- 日期：2026-08-10
- 状态：已接受
- 决策人：洛怜（拍板 M2 底座 crepe_notes）& Teto（M3 编码）

## 背景

M2 双底座验证完成（倾向 crepe_notes 为单声部主底座，ADR-0006/0007），进入 M3 管线闭环：
哼唱 → 转录 → 语义层 → LLM 分析 → MIDI → 钢琴回放能听。M3-TASK 列出 7 项任务，
本 ADR 记录实现中出现的、任务书未提前钉死的决策点。

## 备选方案

1. **fluidsynth 合成方式** —— a) pyfluidsynth ctypes 直调 DLL（`Synth.midi2audio` 文件渲染器，无音频设备依赖）
   b) fluidsynth.exe CLI 子进程（Windows 默认没装）c) pretty_midi.synthesize() 纯 numpy 合成（无钢琴音色，不满足"钢琴回放"）
   → 选 a，DLL 从 FluidSynth 官方 GitHub release 下载放 `vendor/fluidsynth/bin/`（离线可复现）。
2. **SoundFont 来源** —— 任务书首选源 `github.com/dukebw/fluidsynth` 已 404 删除；
   备选 musescore 官方镜像 `ftp.osuosl.org/pub/musescore/soundfont/fluid-soundfont.zip` 有效（126MB，
   内含 FluidR3 GM2-2.SF2，即 FluidR3 家族）。→ 选官方 OSUOSL 镜像，文件落 `vendor/soundfonts/FluidR3_GM.sf2`。
3. **LLM 分析接口容错** —— 推理模型（deepseek-v4-flash 带 reasoning_content）偶发空响应/超时，
   a) 单次失败即降级 b) 重试 2 次 + 空响应回退 reasoning_content + 超时 240s，仍失败才降级空结构。
   → 选 b，管线绝不因 LLM 失败阻塞（ADR-0004 双向拟合降级语义）。
4. **MIDI key signature 映射** —— 大调 = 主音半音序号，小调 = 12 + 主音半音序号（pretty_midi 约定）。

## 决策

1. `tsov/analysis/`：dataset.py 纯规则语义层（音名/相对时值/乐句分组/置信度标签/DSP 特征段），
   prompt.py 固定模板（系统提示 + 数据填充 + DSP 局限说明），llm.py requests 直调 OpenAI 兼容端点
   （Authorization: Bearer $OPENCODE_GO_API_KEY），`analyze(voice, llm=True) -> AnalysisResult`。
2. `tsov/midi/export.py`：`score_to_midi` 单轨旋律直写 + 第一个调性候选写入 key signature。
3. `tsov/render/fluidsynth_backend.py`：pyfluidsynth `Synth.midi2audio` 文件渲染（44.1k，GM program 0 钢琴）；
   模块级 `render_midi(midi, wav, soundfont=None)`；`Backend.render(score,...)` 先导 MIDI 再合成。
4. `tsov/pipeline.py`：`run_closed_loop` 对象流 + 每阶段落盘镜像（stage-01~04.json + song.mid + song.wav + run-summary.json）。
5. `tsov/cli.py` 补 `tsov run` 命令；`tests/smoke/test_end_to_end.py` 合成小星星端到端（LLM mock 离线可跑）。

## 影响

- `vendor/` 新增：`fluidsynth/bin/{libfluidsynth-3.dll, fluidsynth.exe, sndfile.dll, SDL3.dll}` + `soundfonts/FluidR3_GM.sf2`（148MB，不入 git，gitignore 需含 vendor/soundfonts、vendor/fluidsynth）。
- 真实哼唱闭环产物 `output/m3-closed-loop/2026-08-10/{song-01,song-02,song-03}/`，3 首 LLM 分析全部真实调通。
- 踩坑记录：LLM 推理模型单次 60s~400s 不等（越大 prompt 越慢），CLI 会话超时需 >10min；cmd 引号转义对中文 `(1)` 文件名不可靠，用 Python glob 处理。
- M4 待办：参考曲目理解器封装、渲染层第二适配器、MIDI 反向导入（midi_to_score）。

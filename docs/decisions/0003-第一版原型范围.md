# ADR-0003 · 第一版原型范围：DSP 双验证 + LLM 分析层 + 模块化渲染层 + 混合自纠

- 日期：2026-08-09
- 状态：已接受
- 决策人：洛怜 & Teto（需求对齐 grill 会话）

## 背景

架构方向已定（ADR-0001/0002），需要把第一版原型（"哼一句 → 出 MIDI → 回放能听"的最小闭环）的范围、技术底座、交互形态一次定清。2026-08-09 调研了现成 DSP 实现（GitHub 扫描 + 网易云哼唱识曲技术解析），并逐项对齐需求。

## 调研结论（DSP 底座）

- **网易云哼唱识曲链路**（UMX 人声分离 → YIN 基音 → 调式/速度无关特征 → DTW+FAISS 检索）：是**检索**（哼唱→找歌），不是**转录**（哼唱→可编辑乐谱）；不输出时值量化/力度/BPM/置信度，不能直接抄，但验证了 YIN 系基音检测是工业级选型
- **spotify/basic-pitch**（5392★）：音频→MIDI 全家桶，最成熟，但为多声部钢琴式设计，对单声部哼唱可能过度设计、分割逻辑偏硬起音
- **xavriley/crepe_notes**（31★，2026-03 活跃）：CREPE f0 → 离散音符 → MIDI，自带 velocity/短音弱音滤波/confidence——正好是脑暴设计的"CREPE + 分割"路线的现成实现
- **ROSVOT**（ACL'24，123★）：鲁棒歌声转录，但依赖 python3.9/torch2.1.1/tensorflow2.9 与 cu128 环境冲突，且面向歌声非哼唱，排除

## 备选方案

1. 方案 A：crepe_notes 做底座 —— 对口轻量，但 31★ 生态小
2. 方案 B：basic-pitch 做底座 —— 成熟保险，但对哼唱可能过度设计
3. 方案 C：两个都试 —— 各跑真实哼唱对比分割质量再定（多花半小时，选型最稳）
4. 方案 D：自己拼 CREPE + 规则量化 —— 控制力最大但重复造轮子

## 决策

**选方案 C（两个都试）**，配套决策：

1. **DSP 底座**：crepe_notes 与 basic-pitch 各跑真实哼唱对比后定；验证素材 = 用户已有未打标哼唱 + 网易云纯人声版歌曲（有 ground truth 可对照），不搭录音入口（文件导入即可）
2. **LLM 分析层**：DSP 出结构化声部对象 → LLM 读数据做分析（调性候选、疑似错音、分段建议、回放音色选择）→ 回放。回放音色仍用中性钢琴，编配留到下一版
3. **双向拟合（关键补充）**：DSP 原始输出（带滑音/噪声/置信度噪声）不能直接喂 LLM——**先用脚本预处理成 LLM 易理解的中间数据集（音符级语义数据）**，**提示词里教 LLM 理解 DSP 输出的特征与局限**（置信度低=可能错音、短音=装饰音倾向等），两层适配
4. **渲染层模块化（DAW 心智抽象）**：渲染层定义完整层级模型 `score → tracks（音轨）→ instruments（乐器/音源）+ effects（效果器链）→ audio`，外加后端适配器接口。fluidsynth 是第一个适配器；Kontakt/合成器/插件链/DAW 宿主（ableton-mcp/K.G.Studio/Tracktion）是后续适配器。第一版只实现 fluidsynth（回放音色中性，符合"回放音色≠成品音色"原则），接口按终局形态一次定对
5. **自纠 loop（混合）**：DSP 环节（哼唱→声部对象→MIDI）自动评估迭代——音准/时值/置信度都是可量化指标，机器自己收敛；音乐性判断（调性/和声/编曲走向）人在环——无客观标准，必须人听
6. **运行环境**：笔记本开发 + CPU 跑通原型（DSP 管线全 CPU 可跑）→ 验证定案后部署台式机（5060Ti 加速 CREPE/basic-pitch）；代码最终进本仓库
7. **agent loop 形态**：自己写轻量领域 loop（状态机：等输入→分析→渲染→评估→改→再渲染），不魔改 opencode——通用编码 agent 的 loop 与音乐领域对象耦合太深；LLM 调用用标准库/现成 provider，工具 schema 按 MCP 风格设计（将来可挂进 Hermes/opencode 当 MCP server）

## 影响

- 第一版产物：哼唱 → 结构化声部对象 → LLM 分析报告 → MIDI → fluidsynth WAV 回放，全链路可跑
- 验证指标：真实哼唱（用户音频 + 网易云纯人声版对照）的音符命中率、时值对齐、置信度外显质量
- 笔记本需装：crepe/torchcrepe、basic-pitch、madmom、pretty_midi、fluidsynth + 钢琴 soundfont
- 下一版候选：LLM 编配层、多段哼唱对齐、录音入口、渲染层第二适配器

# ADR-0006 · M2 执行细则：乐句分割 / 评估指标 / 真值来源 / 素材矩阵 / 底座判定规则

- 日期：2026-08-10
- 状态：已接受
- 决策人：洛怜 & Teto（grill 断点续接轮）

## 背景

ADR-0005 遗留两项待定：乐句分割（Q25）与评估指标（Q8）。M1 脚手架不阻塞，但 M2 双验证（crepe_notes vs basic-pitch）前必须定死——M2 的验收物（对比报告）依赖评估体系与素材矩阵，而分割方案直接影响报告里乐句层的呈现。本轮 grill 一并钉死。

## 决策

### 1. 乐句/段落分割（Voice.segments）：规则+启发式（Q25 定案）

- 第一版：**规则+启发式**——停顿（静音 >N ms）、置信度低谷、音高突变三信号切分
- 零额外依赖（不引 madmom onset / librosa segment），逻辑透明可调参
- 哼唱素材的停顿/音高突变就是天然分隔符，简单素材够用
- **后续演进**：LLM 语义校正（规则粗分 + LLM 校乐句边界）——等规则版跑出真实数据后再设计，第一版 LLM 保持只读（ADR-0005 精神）

### 2. 评估指标（FR-09 落地）：参考谱对比为主 + 自足指标先行（Q8 定案）

- **主指标（M2 定胜负）**：音符级**精确率/召回率**——以参考谱（ground truth）对比转录结果
- **先行试探**：自足指标（不依赖外部真值）——音准偏差（平均 cents + 分布）、时值误差（onset 对齐）、置信度分布（平均/低置信度音符占比）、音符数合理性
- **执行顺序**：先用自足指标跑通"无标准的准确率"（哼唱素材无真值）→ 再从成品曲扒谱建立标准 → 上音符级精确率/召回率

### 3. ground truth 来源（Q8a 定案）：现成 MIDI 为主 + 独立工具补缺

- **现成 MIDI 为主**：中文流行歌优先（freemidi/bitmidi/乐谱站资源多），覆盖不了的用独立工具补
- **独立扒谱工具补缺**：工具不参与 M2 对比（如 antimetal 等第三方扒谱器）
- **铁律**：真值来源必须独立于候选底座——**禁止用 crepe_notes / basic-pitch 自身扒参考谱**（既当选手又当裁判 = 对比无效）

### 4. 素材矩阵：双轨并行子集版

- **哼唱子集**：6-8 个（先挑相对干净的，降噪未全验证前不全量跑）
- **人声子集**：有现成 MIDI 的 5-10 首（跑参考谱对比）
- 两轨同一次 M2 都跑，报告骨架一次搭好；跑通后全量批量扩（31 哼唱 + 40 人声）

### 5. 底座判定规则：预设透明规则 + 人在环拍板

- 预设规则（写进对比报告模板）：
  1. 音准（精确率/召回率）优先——差距 ≥5 个百分点直接定胜负
  2. 差距 <5% → 看时值对齐误差
  3. 仍接近 → 看资源成本（推理耗时/显存/依赖重量）
- 报告自动给出倾向结论，**Hermes 转述 + 洛怜拍板**（不自动定死，符合"人在环"开发模式）

## 影响

- M1 脚手架不受影响（分割/评估函数先留接口，M2 前填充）
- M2 验收物 = 对比报告，含：素材清单（run-id 可复现）、两底座统一 schema 输出、自足指标表、参考谱精确率/召回率、判定结论（倾向 + 待拍板项）
- 评估函数放 `tsov/eval/`：`self_contained.py`（自足指标）+ `reference.py`（参考谱对比），接口先建，实现 M2 填充
- opencode 迭代不许改这些接口（除非先写新 ADR）

# ADR-0019 · 版本留存分层：双账本（快照窗口 + git 收藏）——部分修订 ADR-0015

- 日期：2026-09-20
- 状态：已接受
- 决策人：洛怜（逐问拍板）｜起草：Hermes/Teto

## 背景

- 现行（ADR-0015 / Q30）：**每操作 / 每轮对话一个 git commit（全持久）**。实测堆积：v22-audit **66 条**、t2 29 条、raw 9 条（一次音量微调 = 一个版本）。洛怜判断："不能每次操作都留一个 git，消耗资源太大并且容易堆积。"
- 洛怜方向（2026-09-18）：**两条线**——弱留存（用户操作 **20 步** / 对话 **5 轮**滑动窗口，自动清理）；强留存（**收藏** + 长线任务完成后**自动收藏**）。关键诉求：**每次收藏都应是"阶段性成果"，不卡在某两步编辑间**。
- 现成积木：ActionJournal（批B 建成：内容寻址快照 + 窗口 + GC，**弱留存原型**）；`fav/<ts>` 收藏 tag。

## 备选方案

1. **单账本（git）+ 自动折叠**（旧 commit squash 进基线）——动历史、风险高（否）。
2. **双账本（采用）** —— 弱 = 快照窗口；git 只装强留存；复用 ActionJournal 机制。
3. **存储不动、视图层折叠** —— 不治"堆积"本体（否）。

## 决策

1. **弱留存 = 快照窗口**：用户手势 **20 步** / 对话轮 **5 轮**；内容寻址快照 + 超窗淘汰 + GC（复用 ActionJournal 机制）；持久化（服务重启不丢）。
2. **强留存 = git 收藏**：仅在 ①手动收藏 ②自动收藏 ③手动"保存版本"时 `commit + tag`（+ 初始基线）。**ADR-0015「每轮一 commit」语义就此部分修订。**
3. **自动收藏规则**：计数 = 自上次 git 点以来 **agent 迭代轮数**（同 `AGENT_MAX_TURNS` 口径，跨消息/会话累计；**用户手势不计入**）；**≥ 40（默认，设置可调）→ 于轮末**（`_run_agent_session` 收尾/finally，正常/停止/异常都过）**由脚本钩子触发**（确定性代码，**非提示词注入**）→ commit「自动收藏：N 轮迭代」+ `fav/<ts>-auto` + 计数器清零。计数器落工程内状态文件（不进 git）。
4. **定时档**：默认关；开启后每 **30min**（可调）且**有未收藏改动**才收（`fav/<ts>-time`）。
5. 收藏列表标注来源（手动 / 自动·迭代 / 自动·定时），可删。

## 影响

- **UI 口径重做**：回滚下拉 = 「最近窗口（快照）+ 收藏（git）」两段式；「撤销本轮」按窗口语义；听旧版/对比走 ADR-0018 拼装路径。
- 相对 ACE「每轮可审计」叙事调整为「**收藏点可审计 + 窗口内可回滚**」。
- 关联：ADR-0018（manifest 与收藏版本引用）；`docs/M-V7-TASK.md` D2/D3 实施。

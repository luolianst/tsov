# ADR-0002 · 哼唱理解用 DSP+规则；MOSS-Music 定位为参考曲目理解器

- 日期：2026-08-09
- 状态：已接受
- 决策人：洛怜 & Teto

## 背景

需要"理解哼唱"（用户哼一段旋律 → 结构化声部对象）。候选理解引擎是 2026-05 开源的 MOSS-Music-8B（复旦 OpenMOSS，音乐理解模型）。需要实测验证。

## 实测证据（4bit 量化 / RTX 5060 Ti / 2026-08-09）

| 输入 | 结果 |
|---|---|
| 合成小星星 6.3s（裸单音旋律，C 大调）| 感知层部分准（时长/单声部/极简方向）；推断层全幻觉（调性说 C# 小调实际 C 大调——系统性 C# 偏移；编造原声吉他/大提琴/和弦进行）|
| 陈奕迅孤勇者 Live 60s（成品歌，F# 小调）| 强：主题（勇气与自我接纳）、男声主唱、情绪全对；**歌词 ASR 精确命中**（"你额头的伤口，你的不同，不必隐藏"）；调性混乱（C#7/C major/A minor 乱猜）；编曲建议偏（说民谣，实际流行摇滚）|

结论：裸哼唱是模型分布外输入 → 先验回归编造"期望听到"的东西；成品歌是舒适区。

## 备选方案

1. 方案 A：MOSS-Music 直接做哼唱理解 —— 实测幻觉严重，否决
2. 方案 B：DSP+规则管线（CREPE 音高跟踪 + CREPE Notes 音符分割 + madmom onset/节拍 + 规则量化）—— 成熟可靠可调试
3. 方案 C：训练专用"哼唱→符号音乐"端到端模型 —— 数据稀缺（哼唱音频+MIDI 配对数据集几乎没有）、黑盒难控

## 决策

选方案 B，MOSS-Music 降级用于参考曲目理解：
- L0/L1（音高/时值/力度/节拍/乐句）：DSP+规则（CREPE / CREPE Notes / madmom）
- L2 语义（成品歌）：MOSS-Music-8B —— "我想要 XXX 那种感觉"场景
- 调性推断：DSP（madmom Krumhansl-Schmuckler）+ 候选分布输出，低置信主动问用户
- 意图层（拟声→音色语义）：直接问 + 打标学习（见 Q10）

## 影响

- 推理参数：必须 `repetition_penalty=1.2`（否则输出退化数字重复）；`max_new_tokens=256`；长音频截断 60s（243s 卡 20 分钟）
- 性能：4bit 加载 15-40s、单次推理 30-60s —— 只能异步
- 环境：`D:\tools\MOSS-Music\`（models 18GB + src GitHub 版 + venv torch2.9.1+cu128/transformers4.57.1/bitsandbytes0.50.0）

# ADR-0007 · M1 执行定案：依赖安装路径（crepe 权重预置 / numpy<2 兼容 madmom / basic-pitch 走 onnxruntime）

- 日期：2026-08-10
- 状态：已接受
- 决策人：洛怜 & Teto（Hermes 转述，opencode 执行 M1 时实测定案）

## 背景

M1 依赖安装（`uv sync`，py3.12 / tsov/.venv）连续踩坑，均来自"上游包年久失修 + py3.12 + numpy 2.x"的组合。逐一实测定位，定案如下。

## 实测踩坑与定案

| # | 问题 | 根因 | 定案 |
|---|------|------|------|
| 1 | `crepe==0.0.16` 构建失败 | ① legacy setup.py 在构建时从 GitHub 下载 5 个模型权重（联网超时）；② 新版 setuptools 移除了 `pkg_resources` | **权重预置本地源码**：下载全部 5 个 `.h5.bz2`（~111MB）解压进 `vendor/crepe-0.0.16/crepe/*.h5`，`pyproject.toml` 用 `[tool.uv.sources] crepe = { path = "vendor/crepe-0.0.16" }` 走本地源码；构建环境补 `setuptools<75` |
| 2 | `madmom==0.16.1` 构建失败 | legacy setup.py 缺 `Cython`/`numpy` 构建依赖 | `[tool.uv.extra-build-dependencies] madmom = ["Cython", "numpy"]` |
| 3 | madmom 运行时 `collections.MutableSequence` / `np.float` 报错 | 2020 年的包：`collections.MutableSequence` 在 py3.10 移除；`np.float`/`np.int` 等别名在 numpy 1.24 移除 | ① `from collections import MutableSequence` → `from collections.abc`（processors.py）；② `np.float`/`np.int`/`np.bool`/`np.object` → 内建 `float`/`int`/`bool`/`object`（全包 .py 批量替换，site-packages 内补丁） |
| 4 | `basic-pitch>=0.4.0` 无解 | Windows+py3.12 时其元数据强制 `tensorflow>=2.4.1,<2.15.1`，该区间无 cp312 wheel | **重写其元数据**：`[[tool.uv.dependency-metadata]]` 去掉 tensorflow、改 `onnxruntime`（basic-pitch 自带 ONNX/TFLite 模型，无 TF 时自动回退 ONNX，`__init__.py` 优先级 TF→CoreML→TFLite→ONNX） |
| 5 | torchcrepe 经 resampy 解析到 `numba 0.53.1` | 解析器选了过低版本，llvmlite 0.36 无 cp312 wheel | `[tool.uv] override-dependencies = ["numba>=0.60"]` |
| 6 | scipy 1.18 + numpy 1.26 不兼容 | scipy 1.18 要求 numpy>=2.0 | 补 `scipy<1.14`，锁到 numpy 1.26 兼容世代 |
| 7 | numpy 2.x 与 madmom/crepe 不兼容 | `np.float` 等别名在 numpy2 移除 | `override-dependencies = ["numpy<2"]`（最终 override 列表见 pyproject.toml） |

## 决策

1. **依赖版本以"能装、能导入"为准，全部钉在 pyproject.toml 里**（override/sources/metadata 三处），不妥协给某个上游包单独开 pip 例外（保证 `uv sync` 一键可复现）
2. **crepe 权重入库 vendor/**（gitignore 除外？——权重 ~180MB 解压后，**不入 git**，见影响）
3. **madmom 的 site-packages 补丁**（MutableSequence + np 别名）：madmom 无新版，补丁是社区通行做法；补丁脚本沉淀到 `scripts/patch_madmom.py` 以便重装后可重放
4. **basic-pitch 走 onnxruntime**：M2 对比时用 ONNX 推理（比 tensorflow 轻且 py3.12 可装），若 M2 发现 ONNX 与官方 TF 结果有差异，再评估装 tensorflow-cpu（2.15.0.post1 有 cp311，需降 py3.11——暂不）
5. **crepe（TF 版）在 M1 只保证 import 不保证 predict**（predict 需 tensorflow，未装）；M2 crepe_notes 底座若用 torchcrepe（torch 版）则无此问题——留给 M2 验证

## 影响

- **vendor/crepe-0.0.16/**：含 5 个 .h5 权重（~178MB），**不入 git**（`.gitignore` 加 `vendor/`；权重来源可重下：`https://github.com/marl/crepe/raw/models/model-<cap>.h5.bz2`）
- **pyproject.toml** 新增三块：`[tool.uv.sources]`、`[tool.uv.extra-build-dependencies]`、`[[tool.uv.dependency-metadata]]`、`[tool.uv] override-dependencies`——均为实测必要，勿删
- **脚本**：`scripts/patch_madmom.py`（madmom 补丁重放）；`scripts/transcode_denoise.py`（M1 音频预处理）
- **验证**：`uv sync` 全绿（89 包）、14 个 pytest 全过、basic-pitch ONNX 推理跑通、3 个哼唱转码降噪产物落盘 `output/m1-preprocess/`
- 若换机器/重装：`uv sync` 自动重放全部依赖坑解法；madmom 补丁需重跑 `scripts/patch_madmom.py`（补丁已记录在 handoff 踩坑表）

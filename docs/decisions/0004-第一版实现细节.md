# ADR-0004 · 第一版实现细节定案：单段优先 / 两层 schema / 降噪 / 里程碑

- 日期：2026-08-09
- 状态：已接受
- 决策人：洛怜 & Teto（grill 需求对齐收尾）

## 背景

ADR-0003 定了第一版范围（DSP 双验证 + LLM 分析层 + 模块化渲染 + 混合自纠），但实现细节还有一批分叉：单段 vs 多段、schema 粒度、自动评估 loop 的深度、降噪方案、开发执行节奏。grill 逐项对齐。

## 决策

1. **单段优先**：第一版只处理单段哼唱（哼一句 → 声部对象 → 分析 → 回放）。多段对齐（关系询问纵向/横向 + 递归锚定，脑暴 Q9 设计）整个留第二版——先验证单段转录质量，别让对齐复杂度污染第一版结论
2. **两层 schema**（第一版定形）：
   - **原始层**（DSP 直出，机器读）：`{bpm, bpm_confidence, notes:[{start, end, pitch_hz, pitch_midi, velocity, confidence, deviation_cents, is_ornament}], segments:[{start, end, type}]}`
   - **语义层**（预处理后喂 LLM，人读）：音符转音名/相对时值/乐句分组，置信度转"存疑/可靠"标签，附 DSP 特征说明——双向拟合第一层的产物
3. **评估指标输出，不自动迭代**（FR-06 降级为 P1 的部分实现）：第一版算出音准偏差/时值误差/置信度分布写进报告（LLM 分析可引用、人可看），**不自动重试调参**——先积累"哪些指标值得自动迭代"的经验，自动重试 loop 第二版做
4. **降噪 = noisereduce**：`pip install noisereduce`（spectral gating），对哼唱素材的底噪/环境音（风扇/空调/底噪）效果好，批量自动跑不需手动标噪音段
5. **git 本地迭代，无 remote**：开发在台式机项目文件夹由 opencode 迭代，本地 git 版本管理（git-guide.md 约定），GitHub 备份暂缓
6. **tsov 包结构**（仓库内建包，分层）：`tsov/core`（数据模型）、`tsov/dsp`（转录）、`tsov/analysis`（LLM 分析）、`tsov/render`（渲染适配器）、`tsov/midi`、`tsov/eval`、`tsov/cli.py`；依赖装 `tsov/.venv`（独立于 MOSS-Music 环境）
7. **双轨执行**：工具层（dsp/render/eval 的 CLI 入口，opencode 和 Hermes 都能调）+ 独立分析 loop（tsov 自写）——将来整个包可挂 Hermes/opencode 当 MCP server
8. **Hermes 角色 = 远程监工 + 转述者**：用户不在台式机前时，Hermes 监控 opencode 进度、推送、转述反馈；用户在台式机前直接操控 opencode，Hermes 不插手
9. **四里程碑**（每完成一个验收再派下一个）：
   - M1 环境+底座：tsov 脚手架 + venv + 音频预处理（转码+降噪）
   - M2 DSP 双验证：crepe_notes vs basic-pitch 真实哼唱对比（统一 schema + 评估指标），出对比报告定底座
   - M3 管线+闭环：完整管线（哼唱→转录→双向拟合→LLM 分析→MIDI→fluidsynth 回放）
   - M4 人在环验证：Hermes 转述通道（WAV 发对话 → 用户反馈 → 转述 opencode 迭代）

## 影响

- 验证素材已就位：`samples/raw/`（哼唱 31 个 m4a + 纯人声 40 个 mp3，2026-08-09 移入，原桌面「测试音频」已删）
- 哼唱素材大部分带环境噪音，FR-08 转码（ffmpeg → 16kHz 单声道 wav）+ 降噪（noisereduce）是 M1 必须项
- 第二版候选：多段对齐、自动重试 loop、LLM 编配层、录音入口、渲染层第二适配器

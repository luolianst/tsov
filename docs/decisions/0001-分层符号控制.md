# ADR-0001 · 音乐生成采用"分层符号控制"而非端到端生成

- 日期：2026-08-09
- 状态：已接受
- 决策人：洛怜 & Teto

## 背景

为什么需要这个决策？
Suno 类端到端生成（文本→音频）存在结构性缺陷：节奏不准（音频域无量化锚点）、分轨奇怪（无真实轨道语义）、音色漂移（乐器人声共用潜空间）、抽卡式（无法迭代局部修改）。用户需要**可控、可编辑、专业音色**的音乐工程。

## 备选方案

1. 方案 A：端到端音频生成（Suno 路线）—— 上手快，但不可控，且无法展现音源/合成器特色
2. 方案 B：分层符号控制 —— agent 管决策（旋律/和弦/结构/编曲，符号域），音源管发声（VST/合成器，音频域）
3. 方案 C：MCP 直控现有 DAW（Cubase 等）—— 复用音源生态，但 Cubase 无官方脚本 API（仅 MIDI Remote 桥接，脆弱）；Ableton 有成熟 MCP（ahujasid/ableton-mcp 2.4k stars）可作渲染层

## 决策

选方案 B（+ C 的渲染层部分）：
- 决策层：LLM + 符号音乐表示（MidiTok/结构化 DSL）
- 表示层：agent 原生"乐曲对象"（调性/和弦进行/轨道/音符/自动化，带置信度）——这是与 Suno 拉开差距的核心
- 渲染层：MCP 接 Ableton/Reaper 复用商业音源，或自建轻量引擎（K.G.Studio / Tracktion Engine）
- Cubase：不碰（无脚本 API，等 Steinberg 开放）

## 影响

- 需要定义表示层 schema（后续工作）
- 渲染层候选已调研：ableton-mcp、K.G.Studio（浏览器 DAW+LLM agent，23 stars）、Tracktion Engine

# ADR-0027 · 显式冻结（freeze/unfreeze）边界与工程状态

- 日期：2026-10-19
- 状态：已接受
- 决策人：洛怜（grill 2026-10-19 拍板）、Teto（实现）

## 背景

实时引擎已把插件轨接入 sidecar，但重插件轨常驻会占 CPU/内存并带来实时风险。v0.2 需要一个用户可见、可逆、可跨会话的冻结能力：把轨的「音源 + 轨插入效果」烘成音频资产，实时播放改走资产并停插件；解冻恢复插件。它与隐形的 stem 缓存、普通导出不同，必须有显式工程状态和命令层入口。

## 备选方案

1. 隐形缓存自动跳过插件 —— 用户不可见、不可诊断，不能解决重工程的明确状态问题。
2. 片段级冻结 —— 粒度更细，但与现有 stem 缓存/轨级渲染边界不一致，首版成本高。
3. 轨级显式冻结 —— 与 ADR-0018 同刀口（效果后/推子前），复用内容寻址 stem 存储；首版采用。

## 决策

采用**轨级显式冻结**，全部决定如下：

- **FZ1** 一条轨一个冻结状态/一条资产；片段级等真实需求再开。
- **BK1** 烘焙边界 = 音源 + 该轨插入效果（效果后、推子前）；轨音量/声像/mute/solo/automation/bus 效果保持实时。
- **LK1** 冻结期间锁源侧（音符/Part/音源/插入效果/参数），混音侧可调（音量/声像/mute/solo/automation 的 volume/pan/bus 路由/总线效果）；改源侧须先解冻。
- **AU1** sidecar 增加通用音频源；冻结资产与普通音频轨走同一路径。
- **ST1** 复用 `.stem-cache/` 内容寻址资产，`Track.freeze` 记录 asset id/指纹；`cache/gc` 尊重冻结资产 pin。
- **FS1** `Track.freeze` 持久化；`freeze_track` / `unfreeze_track` 命令层 op；UI/agent/MCP 同一路径；撤销/重做沿用 EditBatch。
- **FT1** 仅 MIDI/插件轨（VST3/SF2/SFZ）；音频轨不冻结；**V21** v0.2 不支持 VST2 冻结（数据保留、可离线导出）。
- **FR1** 解冻只解 pin，资产保留；物理删除由 `cache/gc` 或显式清理完成；重冻同内容可复用。
- **EX1** 导出直接读冻结资产，不加载原插件；资产缺失/过期 → 409 `stale`，不静默重渲。
- **OP1** 冻结前停播 → 渲染 → 自动恢复原播放位置（失败则提示手动播放）。
- **UI1** 单轨手动（轨道右键/轨道头），失败只影响该轨；批量后续复用同一 op。
- **STL1** 打开/播放/导出前校验资产存在与内容指纹；stale/missing 显式失败，UI 提供重冻/解冻，绝不自动解冻。
- **TS2** 资产范围 0 → 轨内容末尾 + 1s 释放 + 效果 tail。

## 影响

- 工程文件新增 additive 字段 `Track.freeze`；旧工程无需迁移。
- 冻结资产与 stem 缓存共享目录，GC 必须 pin；用户素材不混入冻结资产。
- VST2 轨不显示冻结入口；数据保留、可离线导出。
- 后续扩展：片段级冻结、实时效果链进侧、冻结批量操作再议；不改变本 ADR 的轨级/效果后推子前刀口。

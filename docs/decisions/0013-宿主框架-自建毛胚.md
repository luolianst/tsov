# ADR-0013 · 宿主框架自建毛胚：接口完整预留（音源/插件标准兼容）

- 日期：2026-08-15
- 状态：已接受
- 决策人：洛怜（拍板：自建毛胚 + 预留完整接口，兼容现有音源与音乐插件标准）

## 背景

host = tsov 自己的回放/渲染宿主（score→tracks→instruments+effects→audio，ADR-0003 DAW 心智在**产品内**的落地），替代「fluidsynth 离线文件渲染」，成为可交互的回放心脏；Reaper ReaScript 仍是外部可视化/验收通道，宿主是产品内的。现有宿主产品已论证不可用：Tracktion Engine 的 Python 绑定实测会崩（JUCE forum 实证），Ableton MCP / K.G.Studio 是外部 DAW / 浏览器方案。

## 备选方案

1. Tracktion Engine（Python 绑定）——会崩，底座不可靠。❌
2. Carla / Element（插件宿主）——抄接口设计（engine/track/plugin graph 心智），不抄代码。✅（参考，非底座）
3. 纯 fluidsynth 文件渲染（现状）——无 transport、无插件接口，无法承载「对话→改→回放」交互。❌
4. **自建毛胚（本 ADR 定案）**——初版实现深度浅，但接口一次给全：音源/插件标准按行业标准对齐；实现底座用现成库（pyfluidsynth / pedalboard / popsicle），不重写标准。✅

## 决策

新增 `tsov/host/` 五件套（接口冻结，实现可浅）：

| 模块 | 职责 | 初版实现深度 |
|------|------|-------------|
| `engine.py` | `HostEngine`：load(Score)→Session / render(离线) / play(实时) | ✅ 实现 |
| `session.py` | `HostSession`：score→tracks→instruments→graph | ✅ 实现 |
| `instrument.py` | `SoundSource` 接口：load(格式)/programs/render(notes→audio)；`SF2Source`（pyfluidsynth 实时流渲染） | SF2 ✅；VST3/SFZ 接口 + 桩 |
| `effect.py` | `EffectProcessor` 接口：process(audio)；VST3/CLAP 适配预留 | 接口 + 桩 |
| `device.py` | 混合输出：多轨 mix + 写 WAV（soundfile）；实时播放（sounddevice） | ✅ 实现 |

**标准兼容清单**：SF2/SF3（pyfluidsynth 现成）、SFZ（接口预留）、GM program（沿用 `midi/export.GM_PROGRAMS`）、MIDI 1.0（mido/pretty_midi 现成）、VST3/CLAP（接口预留；底座候选 pedalboard——实测支持加载 VST3 并对乐器发 MIDI、popsicle 备胎）。

**关键技术决策（毛胚防翻车）**：
- 实时回放 = **预渲染缓冲 + sounddevice 流输出**，不在回调线程里实时调度合成（音频线程问题隔离到里程碑二）。
- 离线渲染与实时回放走**同一 graph**（同一 `render()` 产物，只是出口不同）。
- 每轨一个 SF2Source（独立 Synth 实例）——音符数/轨数小规模够用；多轨规模化后再共享 engine（接口已隔离，只换实现）。
- 对外控制协议沿用 Stratawright 分析沉淀的 daw-cli 心智（9 动词 + 标准错误码 + JSON schema），后续接 agentloop 工具时直接套。

## 影响

- 渲染质量目标：现有 `render_midi`（midi2audio 文件渲染）保持可用，HostEngine 是同一能力的**接口化版本**，不破坏既有管线。
- 依赖新增：`sounddevice>=0.4`（实时输出；缺席时 play 明确报错，render 不受影响）。
- DoD：`tsov agent run` 的「宿主回放」步骤 = HostEngine.render（离线）产出 wav + play（有输出设备时）；验收以 wav 产物 + 音频非静音为准。

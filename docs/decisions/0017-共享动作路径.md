# ADR-0017 · 共享动作路径（新功能必须 agent 可用）

- 日期：2026-09-18
- 状态：已接受
- 决策人：洛怜（拍板）｜起草：Hermes/Teto

## 背景

2026-09-18 的三份调研（`docs/refs/ACE-Studio-2-2026-09-18/01~03`、`docs/refs/FL-Studio-AI-2026-09-18.md`）出现一条**三方独立收敛**的工程结论：

1. **FL Studio（Gopher，2026-07 起可写工程）** ★官方手册原文：
   > "When Gopher interacts with FL Studio, it **works the same way MIDI scripting does**. FL Studio exposes a set of controls, and MIDI hardware, scripts, or Gopher can request information from those controls."
   —— agent 不是后门特权层，而是与 MIDI 硬件、用户脚本**平权的"又一个客户端"**。
2. **ACE-Step-DAW（ACE Studio 官方开源 Web DAW）** 开发规则原文：
   > "**Every feature MUST be operable via `window.__store` API in addition to the GUI.**"
   并把"agent 可用"写进 issue 任务书与验收（例 #463 和弦印章：*"Insert stamped notes through a shared piano-roll action path **so the feature is agent-usable**"* / 验收 *"The same insertion path is reachable through store actions for agent automation"*）。
3. **tsov 自身**：命令层（`Project.apply_batch` / EditBatch 事务 + git commit + 音符级 diff，ADR-0015）已实现"快捷命令 / 手势 / agent 工具同走一条路径"——**但"必须走同一路径"从未成文**。历史上出现过两起同型事故：
   - M-V2.3「单测绿但真实链路断」（空谱创作）；
   - 2026-09-14「脚本直出 score.json 绕开 tsov」（工程可见性事故，批1 修复对象）。

## 备选方案

1. **不立规（现状）**——零成本；但旁路随时再犯，功能与 agent 能力各自漂移，验收无法约束。
2. **只写进单批任务书**——轻；但任务书是一次性的，规则不继承，换批次/换会话即失效。
3. **立规 = ADR + AGENTS.md 硬性规则 + 验收双通道**（采用）——规则进入每个 AI 会话的必读文件（AGENTS.md）与 ADR 体系；成本 = 每个新功能增加一条"agent 路径"验收项。
4. **照搬 ACE-Step-DAW 全套**（CI / PR 双评审 / agent dashboard / 每 5 版全系统测试）——不采用：那是"云端多 agent + 有 remote"的配置；tsov 是**本地单仓（无 remote）+ 单体执行**，借"纪律"不借"重资产"。

## 决策

**立规三条（对 tsov 全体开发者与 AI 会话生效，违反即违规）：**

1. **同一动作路径**：每个新功能——无论 UI 控件、REST 端点还是 agent 工具——**必须经由命令层**（`Project.apply_batch` / EditBatch 事务或既有命令 op）实现；**禁止旁路直写工程文件（`score.json`）**。canvas-only 交互必须提供等价的命令层路径。
2. **agent 可用性进验收**：每批任务书 / 每个功能的验收清单**单列一项**「agent 能用同一动作路径完成该功能」；**Verification 双通道**——人工流程与 agent 流程各写一遍（附可复现命令或断言）。
3. **轻量可编程面**：前端挂 `window.__tsovState`（state.js 只读快照）供 CDP 实测与外部 agent 观察；后续 MCP（`docs/MCP接口-迭代计划-2026-09-18.md`）**直接把同一动作层换协议壳**，不另起一套动作体系。

## 影响

- 后续每批（批B/C/D、MCP 线、M-V6 批4）验收口径增加"agent 路径"一栏；任务书模板同步此要求。
- **批B「工具即控件」是本规则的第一块试验田**：动作卡 = 动作层的 UI 可见化；工具↔控件映射表 = 双向契约（21 工具 ↔ UI 控件）。
- 不为旁路需求开口子（例如临时脚本改谱）——如需一次性操作，走 CLI 既有命令层入口。
- 轻量质量指标（进 README 追踪，不建 dashboard）：**undo 覆盖率** = 有撤销测试的命令层 op / 命令层 op 总数；**工具 UI 呈现覆盖率** = 21 工具中有 UI 路径者数量。
- 反面案例归档：上述两起事故作为本 ADR 的"为什么"，新会话读 ADR 即知代价。

# ADR-0018 · 渲染与缓存机制：轨道级 freeze + 统一 stem 库

- 日期：2026-09-20
- 状态：已接受
- 决策人：洛怜（逐问拍板）｜起草：Hermes/Teto

## 背景

- tsov 现状：整曲离线渲染（FluidSynth + pedalboard 效果链），谱面任何改动 → **整曲重渲**；试听 = 整曲 WAV 加载；`.render-cache/<rev8>.wav` 每版本一份全曲缓存。
- 实证（2026-09-20 实测，t2 工程 6 轨/3100 音/90s）：全曲渲染 5.33s；单轨全链 0.60~1.56s；效果链约占总成本 1/3；**混音拼装≈免费**——成本全在"合成+效果"，而现状把成本与"改动规模"完全解耦。
- 调研（`docs/refs/调研-渲染机制-2026-09-18/报告.md`，23 来源）：主流宿主**播放=实时逐块合成**；离线渲染只用于导出/冻结且**按轨按区域**；**无自动脏区重渲**（五家官方文档均未查到）；缓存失效靠用户显式 freeze/unfreeze；采样磁盘流式。**结论：问题本质 = 缓存粒度太粗（全曲）；轨道级 freeze + 版本内容寻址分块 = 改动最小、收益最大。**

## 备选方案

1. **分段/脏区块缓存** —— 更细粒度；效果尾音/拼接复杂度高（暂缓为升级路径）。
2. **播放端流式取音** —— 治"大 WAV 卡浏览器"的另一条线（暂缓，可随批D 资源基线评估）。
3. **实时合成播放** —— 业界终极形态；需音源/效果实时化 + 浏览器实时引擎，代价大（暂缓）。
4. **止血版（后台渲染队列 + 进度）** —— 不治本（弃）。
5. **轨道级 freeze + 统一 stem 库（采用）** —— 改动最小、与导出分轨同构、升级路径全部保留。

## 决策

1. **粒度 = 轨道级 freeze**：每轨按内容指纹渲一份缓存；**改动只重渲脏轨**。
2. **刀口 = 效果后、推子前**：缓存 = 合成 + 效果链输出；**推子/自动化/声像走混音期实时应用**（永不触发重渲）。为此**管线换序**为 `synth → 效果 → 推子/自动化 → 声像 → 总线 → master`（DAW 标准序；现序为 fader→automation→pan→效果）。
3. **统一 stem 库**：缓存**内容寻址**（键 = `hash(音符 + 音源 backend/program + 效果链参数)`，不含推子/声像/自动化/速度/拍号/总线归属）；**版本 = manifest**（`rev → 各轨 hash`，从 git 计算）；相邻版本天然共享缓存；`.render-cache` 整曲缓存**退役**。
4. **触发 = 按需懒渲**：试听/导出那一刻渲脏轨（进度可见）；**导出永远同步保证全量最新**。
5. **实时层次 = 松手即听**：手势/轮末落盘 → 服务端缓存重拼（亚秒）→ 播放中**位置保持续播**。拖动中本地预览不做（遗留小项）。

## 影响

- **音色变化（须对照）**：换序后推子不再驱动效果输入——非线性效果（压缩器等）行为修正；混响尾巴不再随声像摆位。**孤勇者链（音量 2.0 + 压缩器）等旧产物需新旧对照重跑**；全量测试基线重跑。
- **听旧版/版本对比**：由"每版本整曲 WAV"改为按 manifest 拼装（缺轨即渲）。
- **GC**：stem 库无引用即清（被 HEAD/收藏 manifest 引用者保留）+ 手动入口。
- 升级路径预留（不阻塞本批）：分段脏区 / 后台预渲 / 旧缓存降级播放 / 播放端流式 / WebAudio 本地预览。
- 关联：ADR-0019（收藏版本 = manifest 的消费方之一）；`docs/M-V7-TASK.md` D1 实施。

# ADR-0020 · 架构治理裁定：分层纪律 / 单向依赖 / web 拆分 / 编排面 / 树维护

- 日期：2026-09-23
- 状态：已接受
- 决策人：洛怜（治理任务书 G1–G9 全按默认批准；Teto/Hermes 执行与草拟）

## 背景

2026-09-22 架构 review 轮（只读）以 normify 模块树 + 报告列出七个混乱点 F1–F7；同日批准全量治理任务书（批 1–5），2026-09-22~23 逐批执行完毕（F1–F5 已修，F6 按裁定记载，F7 已补钻）。review 的发现与处置是一次性的；其中四类结构性纪律（分层、单向、web 拆分形、编排面）与树维护方式需要固化为长期约束，防止后续迭代中复发漂移。

## 备选方案

1. **仅任务书/报告记载** —— 一次性文档，无长期约束力，后来者（含 AI 会话）没有"开工必读"的锚点。
2. **固化 ADR（本选）** —— 决策进 `docs/decisions/` 索引，AGENTS.md 落一行硬性规则（树维护），被"新会话先读"流程覆盖。
3. **不记载** —— 依赖口口相传，不可行。

## 决策

1. **分层纪律（F1）**：纯函数工具（音高换算 / 音名 / 调性类）一律归底部 `tsov/core/`；上层需要即向 core 引用；**禁止底层反向 import 上层**（host→analysis/dsp 式反向依赖不再出现，发现即下沉处理）。
2. **单向依赖（F2）**：模块间引用维持单一方向（`host.engine → host.export` 定案），懒加载不改变方向；出现互引时要么在 ADR 记录明确方向、要么摘环。
3. **web 拆分定案（F5）**：`tsov/web.py` = 薄壳（组装 + `tsov web` 入口）；实现按域进 `tsov/webapp/`（config/models/state/helpers/record/agent_session + routes 八域）；新端点一律落对应域模块，不回填薄壳。
4. **编排面保留（F6）**：cli / web / pipeline / agent 四条编排入口**不合并**；行为一致性依靠 ADR-0017 共享动作路径纪律（新功能必经命令层 + 双通道验收）；树中标注为「编排面」。
5. **架构树维护纪律（G9）**：normify 树（`D:/projects/normify-tsov/`）随代码常绿 —— **结构变更后收尾跑 refresh → validate（0 error 才 build）→ build → render**；箭头锚点随结构变更同步；树数据非 git（无回档），大树改动前先整目录备份。

## 影响

- 后续新功能/新模块按本 ADR 检查落点（core 纯工具 / 单向 import / web 域模块 / 命令层路径）。
- review 报告已附处置标注（`docs/refs/架构-2026-09-22/架构review-tsov-2026-09-22.md` §5）；治理执行记录见 `docs/架构治理-任务书-2026-09-22.md`（批 1–5）。
- `AGENTS.md` 开发规则新增「架构树维护」小节（同日本 ADR）。
- 余留 11 条 coarse 提示（支持集/小域）为**已知并接受**状态，非待办。

# ADR-0005 · 系统设计：库+CLI 薄壳 / 对象流+落盘镜像 / 六类数据模型 / JSON 持久化

- 日期：2026-08-09
- 状态：已接受
- 决策人：洛怜 & Teto（grill 系统设计轮）

## 背景

需求对齐完成（ADR-0003/0004），进入系统设计。vibe coding 产物必须先定架构、模块、数据模型、持久化，防止实现跑偏。本 ADR 钉死第一版的工程骨架。

## 决策

### 1. 整体形态：库 + CLI 薄壳
- `tsov` 是纯 Python 库，模块间直接 import 调用
- CLI 是薄入口（`tsov transcribe xxx.wav` / `tsov analyze` / `tsov render` 等命令）
- 将来服务化 / 挂 MCP server 时直接包库，不重构

### 2. 管线产物流转：进程内对象流 + 落盘镜像
- 管线运行时模块间直接传 Python 对象（Note/Voice/Score 实例）
- 每个阶段关键产物同时落盘 `output/<run-id>/stage-XX.json`——调试/复现/LLM 读取都从文件来
- run-id 机制让每次验证可复现（M2 对比测试、M3 闭环都是 run 制）

### 3. 核心数据模型（六类全定，表示层本体）
```python
# tsov/core/notes.py
@dataclass
class Note:
    start: float          # 秒（绝对时间）
    end: float            # 秒
    pitch_midi: int       # 量化后 MIDI 音高
    pitch_hz: float       # 原始频率（DSP 直出）
    velocity: float       # 0-1 力度
    confidence: float     # 0-1 转录置信度
    deviation_cents: float  # 相对量化网格的音分偏移（表现力保留）
    is_ornament: bool     # 装饰音标记（短音/倚音倾向）

@dataclass
class Voice:              # 一段哼唱 = 一个声部
    notes: list[Note]
    bpm: float
    bpm_confidence: float
    segments: list[Segment]   # 乐句/段落 {start, end, type}
    source_audio: str         # 来源文件路径（溯源）
    backend: str              # DSP 后端（crepe_notes/basic-pitch）

# tsov/core/score.py
@dataclass
class Effect:
    type: str             # "reverb" / "compressor" / ...
    params: dict          # 参数表

@dataclass
class Instrument:
    backend: str          # "fluidsynth" / "kontakt" / ...
    program: str          # 音色/预设标识
    volume: float
    effects: list[Effect] # 效果器链（第一版可为空）

@dataclass
class Track:
    name: str
    instrument: Instrument
    notes: list[Note]

@dataclass
class Score:
    title: str
    tempo: float          # BPM
    key_candidates: list[KeyCandidate]  # 调性候选分布 {key, confidence}
    tracks: list[Track]
    meta: dict            # 生成元信息（run-id/时间/来源）
```

### 4. 持久化：JSON 文件系统（第一版）
- `output/<run-id>/` 目录 = 全部持久化（stage JSON 镜像 + 报告 + WAV/MIDI）
- `output/runs.json` 索引：run-id → 时间/输入/状态/结论
- 零数据库依赖，产物目录可整包拷贝复现，opencode 翻文件零学习成本
- 版本树（对话/版本节点/回退/分支）+ SQLite：**第二版**对着真实多轮数据再设计（第一版无多轮迭代场景，建了是空壳）

### 5. 语义层生成：固定模板 + 规则填充
- `tsov/analysis/dataset.py`：纯规则把原始层转成语义层（音名/相对时值/乐句分组/置信度标签）
- `tsov/analysis/prompt.py`：固定提示词模板 + 数据填充 + DSP 特征/局限说明段
- **确定性、无 LLM 参与生成**——LLM 只负责"读+分析"。保证 M2 双底座对比公平（同样输入同样模板，差异只来自底座）

### 6. 双轨调用：进程内 import + CLI 薄壳
- 分析 loop 直接 import 工具函数（transcribe/quantize/render 就是普通函数）
- CLI 只是这些函数的薄壳；opencode/Hermes 远程调走 CLI 入口
- 同一套函数两种入口；将来跨机拆分时接口就是函数签名，拆起来干净

### 7. 配置：代码内默认值 + CLI 覆盖
- 不搞配置文件（YAML/TOML/env 都不用）
- DSP 参数是代码里带默认值的常量/数据类，CLI 参数覆盖关键项（`--noise-reduce-strength 0.7`）
- 调参即改代码，git 天然记录每次调参历史（run 镜像同时有代码版本和参数）

### 8. 测试：三层
- `tests/unit/`：纯函数逻辑（序列化/量化规则/语义层转换），pytest
- `tests/compare/`：M2 专用——同一哼唱样本喂 crepe_notes/basic-pitch，统一 schema + 评估指标对比，产出对比报告 = M2 验收物
- `tests/smoke/`：M3 专用——端到端跑通（合成小星星 wav → 全管线 → 出 WAV+MIDI+报告），断言产物存在且非空

### 9. 依赖：uv 管理 + `tsov/.venv`
- `pyproject.toml` 声明全部依赖（noisereduce/crepe/torchcrepe/basic-pitch/madmom/pretty_midi/fluidsynth/soundfile），`uv sync` 生成 lock
- 独立于 MOSS-Music 的 torch2.9.1+cu128 环境
- 台式机坑现成解法：uv trampoline 坏 → `uv python install 3.12`；全路径 `uv.exe pip install --python`；安全软件锁文件等 30-60s 重试

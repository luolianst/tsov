# ADR-0024 · 架构树数据 git 化

- 日期：2026-10-09
- 状态：已接受
- 决策人：洛怜（Teto 执行）

## 背景

ADR-0020 第 5 条为 normify 架构树定了维护纪律，其中一句是：「树数据非 git（无回档），大树改动前先整目录备份」。实践下来这笔账越来越贵：备份粒度只有「整目录快照」一档——2026-10-08 单日就累积 3 份 `*.bak-*` 快照（工作台v2 / C2 / c前段），再加一份更早的 e5s3 旧 zip；无 diff、无检索、回档只能整目录替换，「记得先备份」也纯靠人工纪律。

## 备选方案

1. **维持整目录备份** —— 零学习成本；但备份持续堆积、粒度粗、纪律不可靠（单日 3 连快照即实证）。
2. **树数据转本地 git 管理（本选）** —— 回档点 = 提交点，可 diff / 可检索；与「每批收尾一次提交」的工作节奏天然契合；成本 = 需要维持提交纪律（改动前确认干净、改动后提交）。
3. **其余版本工具（定时 zip / jujutsu 等）** —— 收益不抵复杂度，不取。

## 决策

选 2：`normify-tsov` 数据目录（normify rootDir 之下）转为**本地 git 仓库**——2026-10-09 初始提交 `224c749` 上线；`.gitattributes` 锁 LF（`* text=auto eol=lf`），防行尾归一化改写数据字节。树维护纪律随之修订为：

1. **大改前**：`git status` 确认干净（不干净先提交或还原）再动手；
2. **收口**：refresh → validate（0 error 才 build）→ build → render 之后 `git commit`——提交点即回档点；
3. **不再新增整目录 `*.bak-*` 备份**；存量备份清退（3 份 10-08 备份 + e5s3 旧 zip，diff 逐一验证为旧态子集；删档记录 = `docs/refs/整理记录-2026-10-09.md`）；
4. 仅本地仓库、不加远端（树数据属过程档案类，不进公开面）。

## 影响

- **修订 ADR-0020 第 5 条**：其中「树数据非 git（无回档）……先整目录备份」一句由本 ADR 取代；同条中的树路径 `D:/projects/normify-tsov/` 为笔误，实际路径为 `D:/My Project/normify-tsov/`（AGENTS.md 已同步更正）。
- 树收口流程本身（refresh → validate → build → render）不变；收口后补一次 commit。
- `normify-geyun` 树暂不强制同规（同工具链，后续可照此办理）；树工具链（normify-adapter）不受影响。
- 相关运维口径同步：技能 `normify-arch`（「大改前整目录备份」→「大改前 git 干净基线」）。

# 技能写作规则（tsov 内置技能维护指南）

适用：维护 `tsov/agent/skills/*.md` 与外部投放技能。来源：ACE Studio skills 精读可借鉴清单
（2026-09-18）+ 本项目实战教训。

## 结构
- **编排层 · 机制层分离**：技能正文只写「什么时候干什么、怎么选」（编排）；工具参数细节、
  数值口径等机制事实由工具 schema / docstring 承载，正文不复制（会漂移）。
- **description 场景化**：frontmatter description 写「何时加载我」——触发场景词（「当……时加载」），
  不写内容目录；catalog 原样展示给模型做加载决策。
- **references 分层（渐进披露）**：正文 = 决策树 + 短指引；细节拆 `skills/references/*.md`，
  正文用「按需 read_text 读取」指路。注意：references 子目录**不被 SkillLibrary 扫描**
  （非递归 glob），不会误当技能加载——但也别把必须随技能加载的内容放进去。
- **负面情报坦率**：已知坑 / 失败路径 /「别做什么」必须写进正文——踩过的坑不写 = 下个会话必重蹈。
- **防自欺句**：涉及验证的步骤写明「怎么算过」（可复核的口径），禁止「看起来对就行」。
- 一条规则一件事；带日期的一次性事件不入正文（去 handoff / 总册）。
